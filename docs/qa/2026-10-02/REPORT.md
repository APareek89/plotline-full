## What changed

- **Still-image planning:** film screen-time, temporal beats and camera-motion heuristics apply to video only. One person can appear in one still. The actual shot-board prompt asks for one image by default, retains explicit carousels and describes ordinary backgrounds in the prompt instead of buying an unnecessary environment sheet. An explicitly requested reusable location stays supported.
- **Whole-path capacity before spending:** board approval reports minimum canon/keyframe operations, remaining owner/shared lifetime capacity and unknown media USD conversion. Matching saved anchors, sheets and keyframes reduce the remaining count. Capacity is a snapshot; atomic per-request reservations still enforce the limit if another request consumes it. No cap or historical usage was changed.
- **Explicit smaller-plan choice:** a user can review a one-image alternative retaining product/person references and already-paid environment references. It requires a fresh board approval. Merely inspecting an estimate never changes a requested carousel.
- **Existing-campaign recovery:** a new brief clears approval, not paid history. An explicit saved-reference review can recover the latest same-thread canon artifact after reset/restart, validate current product uploads and owned assets, rebind renamed board references, and request approval again. No fuzzy identity matching or silent approval restoration is used.
- **Paid partial-output recovery:** successful canon plans, anchors, sheets and individual keyframes are checkpointed before later work. Input fingerprints include prompts, reference identities, model/provider and settings. Explicit Retry can continue after restart without generating a completed output again. Sharper canon versions preserve the old rows and bindings until the new set completes.
- **Validation and clarity:** unverified real-person rights are rejected before rendering; duplicate/cross-kind canon IDs are rejected. Failure cards have concise titles and safe full explanations, and exhausted allowance does not offer a Retry that cannot repair it. Allowlisted category, exception class, stage and a random support ID are logged and saved in owner activity; raw exception text, provider messages and URLs are excluded, and logging survives unavailable state storage. The UI renders those safe reasons. Video lint no longer claims it automatically split a row when it only recommended an edit.
- **TLS:** Plotline already stripped all URL `ssl*` options; installed-pg tests confirm `ssl=no-verify` cannot replace its explicit CA. Python explicitly disables GSS negotiation so hosted transport stays on the verify-full TLS path. Local PostgreSQL contracts pass.

A subsequent review of the exact affected campaign exposed a separate output-ratio defect: the first brief ratio was square, while Instagram-feed delivery requested 4:5. Still keyframes now use the intended placement ratio, and approved reuse requires matching stored ratio plus verified owned image bytes. Actual raster decoding permits at most 3.5% aspect quantization (for example 896×1152 near 4:5), not a square-to-portrait relabel. Unreadable or mismatched paid frames are retained and held; a saved invalid keyframe checkpoint prevents an identical Retry from buying another image. Approval, reuse, QC and final delivery recheck geometry. Multi-placement outputs/fallbacks are counted before dispatch; duration checks remain `skip` where unwired. The mock 4:5 SVG is also correctly sized. These checks validate free PNG/SVG proxies, not provider fidelity.

A failed capacity job also exposed a recovery-presentation defect: GET correctly retained the generic Retry descriptor, but the page hid newer saved-reference and smaller-plan choices whenever that descriptor existed. The page now prioritizes current non-Retry actions, while preserving the generic banner for legacy Retry-only or free-text asks. A real stored failed-job regression exercises GET, explicit saved-reference review and reload, with all six saved assets unchanged and provider functions forbidden. The refreshed local browser fixture includes that failed job; its earlier version did not. Root browser acceptance confirms both choices were visible, saved-reference review restored three sheets, and reload retained fresh approval without the generic Retry banner. See `recovery-priority.json` and `browser-qa.json`.

Root browser QA also demonstrated a 701px tablet split-pane defect. The web layout now stacks below 960px and keeps sign-out readable; before/after screenshots and the no-overflow/composer dimensions are recorded in `browser-qa.json`. The final AWS web build includes this fix.
